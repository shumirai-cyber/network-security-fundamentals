## 3. Review of the 12 Activities

### Activity 1: Understanding Computer Networks

I learned that computer networks allow devices to communicate and share resources. I explored basic network concepts, including local area networks (LANs), wide area networks (WANs), and the role of network configuration.

I also learned how network configuration information can help troubleshoot connectivity problems.

### Activity 2: IP Addresses and Subnet Basics

I learned that IP addresses identify network interfaces and support communication between devices. I explored IPv4, IPv6, private and public IP addresses, and the purpose of subnetting.

I also learned that subnetting helps organise networks and divide address spaces into smaller networks.

### Activity 3: Understanding Network Ports and Protocols

I learned that network ports help identify the applications or services involved in communication. I explored TCP, UDP, and common service ports, including ports associated with SSH, DNS, HTTP, HTTPS, and Remote Desktop Protocol.

I also learned how Windows networking tools can display connection states and listening ports.

### Activity 4: DNS, DHCP and How Devices Connect

I learned that DNS translates domain names into information used to locate network services, while DHCP helps devices obtain network configuration automatically.

I also explored how these services contribute to connectivity and how DNS lookup tools can assist with troubleshooting.

### Activity 5: Routers, Switches and Network Devices

I learned about the roles of routers, switches, access points, and other network devices.

Routers forward traffic between networks, while switches connect devices within a local network. Wireless access points allow compatible devices to connect over Wi-Fi.

I also explored how traceroute can help investigate the path taken towards a destination.

### Activity 6: Firewalls and Network Security Rules

I learned that firewalls help control network traffic according to security rules. I reviewed the role of Windows Firewall and the importance of restricting unnecessary connections.

I also learned that firewall protection should be combined with other security measures, including software updates, secure configurations, and appropriate access controls.

### Activity 7: Common Network Attacks and Threats

I explored common threats, including phishing, man-in-the-middle attacks, denial-of-service attacks, IP spoofing, and malicious wireless hotspots.

I learned that recognising suspicious activity and verifying information are important steps in reducing cybersecurity risks.

I also learned that different attacks require different prevention and response measures.

### Activity 8: Wi-Fi Security and Secure Connections

I learned about wireless encryption standards, including WEP, WPA, WPA2, and WPA3. I explored why outdated encryption and weak passwords can put wireless networks at risk.

I also learned how to reduce the risks of public Wi-Fi by verifying network names, using HTTPS, updating devices, and following safe connection practices.

### Activity 9: Introduction to Network Traffic Analysis

I learned that network traffic analysis involves examining communication between devices to identify patterns and investigate possible security issues.

I explored the roles of tools such as Wireshark and tcpdump, as well as the importance of understanding network packets and protocols.

I also learned that suspicious traffic must be investigated carefully before conclusions are drawn.

### Activity 10: Practical Network Investigation Using Windows Tools

I reviewed Windows networking tools, including `ipconfig`, `ping`, `nslookup`, `tracert`, and `netstat`.

I learned that these tools can help investigate network configuration, connectivity, DNS resolution, routing, and active connections.

I also learned that the output of these commands can contain sensitive information and should be handled responsibly.

### Activity 11: Network Security Findings and Recommendations

I learned how to identify potential network weaknesses, assess their possible impact, and recommend security improvements.

I explored findings involving weak passwords, unnecessary listening services, outdated software, firewall configurations, and untrusted wireless networks.

I also learned that security findings should be supported by evidence and prioritised according to risk.

## 5. The Importance of the CIA Triad

The CIA triad is a fundamental cybersecurity model consisting of confidentiality, integrity, and availability.

**Confidentiality:** Information should only be accessible to authorised users and systems. Strong passwords, access controls, encryption, and secure network configurations can help protect confidentiality.

**Integrity:** Information should remain accurate and protected against unauthorised changes. Access controls, monitoring, and appropriate security procedures can help preserve integrity.

**Availability:** Systems and information should remain accessible when required. Backups, resilient infrastructure, monitoring, and protection against denial-of-service attacks can support availability.

These principles help explain the objectives of network security controls and the potential consequences of security weaknesses.

## 6. Lessons Learned

The most important lessons from this project are:

1. Network security begins with understanding how devices communicate.
2. Weak configurations and unnecessary services can increase security risks.
3. Firewalls, encryption, secure passwords, and software updates are important protective measures.
4. Network investigation tools provide useful information, but their results must be interpreted correctly.
5. Unusual network activity does not automatically prove that an attack has occurred.
6. Security recommendations should address identified risks and be supported by evidence.
7. Cybersecurity investigations should only be performed on systems and networks where permission has been granted.
8. Protecting sensitive technical information is an essential part of responsible cybersecurity practice.
9. Continuous learning is necessary because technologies, vulnerabilities, and attack techniques change over time.
